# 港股价值评估（降维口径）设计 — stock-value-hk

- 日期：2026-11-13
- 状态：待评审
- 定位：持仓港股的**事实型价值参考**，不是第二套评分。独立表 `stock_value_hk`、独立 Edge Function `stock-value-hk`、独立 cron。**不修改 A 股价值腿的任何规则、权重、表与文案**
- 前置探针：2026-11-13 两轮共 11 次国信 `HK_stock` 通道只读实调（首轮 7 次定位缺口，本轮 4 次锁定查询串与口径）。§2 全部为实测结论，非推测
- 用户裁定四条：①覆盖只限持仓港股 ②报事实 + 8% 作参照 ③新表新函数 ④只走夜间 cron
- 范围关系：本设计**不推翻** `2026-09-26-stock-scoring-v1-design.md` 决议 11（港股不进 A 股引擎）。港股仍不进那个引擎；本设计是在它之外另开一条只报事实的窄通道

## 1. 为什么必须降维，而不是把港股接进现有引擎

现有引擎（`value_engine.ts`）是两层结构：绝对阈值门禁回答「值不值」，组内百分位回答「合格者中谁更靠前」。港股通道缺三样字段、且不返回市场类型，逐条撞在这两层的承重墙上：

| 缺什么 | 撞到哪 | 后果 |
|---|---|---|
| 同花顺行业分类（不返回） | `assignGroupsV` 无组可分 → 全部落 `MARKET` | `indN=0` → `confidence=C` → 被 Top10 与分歧榜的「只取 A 级」排除 |
| 持仓只有 2 只 | `pctFrom` 的 `if (ms.length < 5) continue`（`value_engine.ts:133`） | 组内百分位**结构性不可能产出分**，不是数据不够，是样本量下限 |
| 带息债务（字段不存在） | `investedCapital` 任一缺即 null（`:26`） | `normYield` 整腿 NA |
| FCFF 覆盖 20.4%（腾讯为空） | `ownerYieldOf` 的 cashY 腿 NA（`:36`） | 两腿全空 → `oy=null` → `priceOk=false` → `tier='unqualified'` |
| 股票市场类型（不返回） | `gs_value.ts:203` 的 `!mkt.includes('全部A股(非ST)')` 对 `mkt=''` 恒真 | 每行被判 ST → `value_engine.ts:166` 过滤后 **2792 行全清，无报错、无输出** |

其中两条是**语义错误**，比缺数更严重：

1. `tier='unqualified'`（页面译作「不合格」）在腾讯这一行的真实含义是「FCFF 与带息债务取不到」。把数据缺口翻译成经营结论，正是这套引擎在港股上会犯的最严重的错。
2. 静默清空不产生任何错误信号。批次「成功」、表里零行、页面显示「本批次无该股数据」——与「港股本来就不在范围内」的现状**外观完全一致**，故接线后不会有人发现它坏了。

**降维的实质不是「少报几个数」，而是把三个硬缺口从阻塞项变成不查询项**：不问行业、不问带息债务、不问 FCFF/商誉、不问市场类型 ⇒ 三个缺口一个都不触发，`isST`/`isFin` 也不再需要（港股无 ST 制度）。剩下的只有形态问题（§2 H-2/H-6/H-8），全部在适配器里解决。

代价是明确的、且是用户已裁定的：港股**不存在** tier / vq / confidence / 安全边际 / 同业分位 / 四维雷达 / 门禁明细 / 换仓参考。不是隐藏，是不计算。

## 2. 数据层实测结论（构成硬约束）

### 2.1 三条生产查询串（原样锁定，不得改写）

本轮 4 次调用状态码均 0，其中 3 次确定了下表的生产查询串，第 4 次是裸措辞诊断（只用于确认 H-2 的 7 列形态，**不进生产**）。**措辞是实测锁定的契约，不是可自由改写的自然语言**——首轮已两次观测到 GS 静默丢列与静默换字段。

| 编号 | 查询串（`searchtype: 'HK_stock'`） | 实测返回 |
|---|---|---|
| HK_Q1 | `全部港股的{Y-2}年报投入资本回报率、{Y-1}年报投入资本回报率、{Y}年报投入资本回报率、股票简称` | 恰好 3 根年报列 + 简称 + 代码，2792 行 |

## 3. 口径定义（唯一权威）

三年窗与派生：

- `roic_cur` = 最新年报（Y 年）ROIC
- `roic_med` = 三年中位；**≥2 期有效才计算**，否则 null（与 A 股 `roicStats` 同语义）
- `roic_min3` = 三年最差年；与 med 同一有效期集合，同生同死
- `roic_ok` = `roic_med >= 8`；**med 为 null 时 `roic_ok` 为 null，不是 false**
- `div_yield` = Y 年股息率；`div_yield_5y` = 平台 5 年平均股息率
- `pe` = PE(TTM)；`pb` = PB

**`roic_cur` 与 `roic_med` 相互独立**：只缺最新一期时 `roic_cur=null` 而 med 照样有值，达标判定**只看 med**。这与 A 股决议 29 同口径——「缺最新一期」是数据事实，不得断言成「无护城河证据」这个经营结论。

参照线 **8%**，与 A 股 `ROIC_GATE` 同一个数、同一个理由：它是 WACC 锚，不是行业均值（2026-10-30 裁定维持 8）。港股不做行业调整——本设计既无行业字段，也不做同业比较。

### 3.1 空值语义（逐条明确，不留默认）

| 字段 | 空值处理 | 理由 |
|---|---|---|
| ROIC 各期 | 该期不参与；有效期 <2 ⇒ med/min3 皆 null ⇒ 页面「无数据」 | 不补 0、不用 ROE 替代（见 §3.2） |
| 股息率 / 5 年平均 | null ⇒ 页面「无数据」 | **不沿用 A 股「空 = 从不分红记 0」**（见 §3.3） |
| PE ≤ 0 | null ⇒「无数据」 | 亏损股 PE 无经济含义 |
| PB ≤ 0 | null ⇒「无数据」 | **不推断「资不抵债」**——那是 A 股否决 1 的结论，本设计不产结论 |

### 3.2 为什么不做 ROE 替代

A 股金融股用 ROE 对标 ROIC，前提是能识别 `isFin`，而这靠「股票市场类型」字段。港股不返回该字段（H-4）⇒ **无法识别金融股**。持仓里若出现汇丰 0005、建行 0939 这类，其资本回报行显示「无数据」。

这是已知且接受的边界，写进常驻口径行。**不做按股票名猜行业的兜底**——名字匹配脆弱，且一旦猜错就会把 ROE 当 ROIC 与 8% 比，量纲不同源，等于造出一个假比较（A 股 2026-11-02 裁定③已就同一问题立过规矩）。

### 3.3 为什么股息空值语义与 A 股不同

A 股 P-6 已实测确认「股息率空 = 从不分红」，故记 0 参与排名是真实负面信号。**港股通道没有这个确认**：1006/2792 的覆盖率既可能是从不分红，也可能是平台未回填，两者无法区分。

在语义未确认前记 0，会把「不知道」说成「不分红」——与本设计的立身之本（只报事实）直接冲突。故落 null、显示「无数据」。**若日后确认了港股空值语义，再单独裁定是否改记 0**，不在本设计内预留开关。

## 4. 落库：新表 `stock_value_hk`

```sql
create table if not exists stock_value_hk (
  batch_date date not null,
  code text not null,              -- 5 位补零，与持仓/前端同形（00700 / 09988）
  name text,
  roic_cur numeric, roic_med numeric, roic_min3 numeric,
  div_yield numeric, div_yield_5y numeric,
  pe numeric, pb numeric,
  roic_ok boolean,                 -- med>=8；med 为 null 时此列为 null（三态，不是布尔两态）
  extras jsonb,                    -- { stamps: {列名→日期戳原样}, years: [Y-2,Y-1,Y], missing: [字段名] }
  primary key (batch_date, code)
);
create index if not exists stock_value_hk_batch_idx on stock_value_hk (batch_date);
```

- **只落持仓行**（预期个位数），不落全市场 2792 行。全市场查询只是取数手段，不是落库范围。
- **不设 `rf_fallback`**。A 股那列是 `not null` 且无 default 的 fail-loudly 设计（漏写即整批报错，防「口径不一致伪装成一致」）。港股不算安全边际 ⇒ 该列**不存在**，而不是填 false 撒谎。这是选择新表而非复用 `stock_value` 的首要理由。
- 同理不复用 `stock_value` 的另两个理由：避免十余列恒 NULL；避免逐一审计现有每个 `stock_value` 查询是否需要加市场过滤（`loadStockValue` / `loadIncomeWatch` / `loadValueIndustryRef` / Top10 / 分歧榜 / 换仓，漏一处就把港股混进 A 股榜）。
- RLS 照 `migrate_stock_value.sql` 同一范式：`enable row level security`；`create policy … for select to anon, authenticated using (true)`；`grant select`；`revoke insert, update, delete, truncate, references, trigger`。写路径由「无写策略即拒绝」关闭，夜间函数走 `service_role` BYPASSRLS。
- 迁移文件：`scripts/migrate_stock_value_hk.sql`，回滚 `drop table if exists stock_value_hk;`
- **执行迁移需用户明示**，与 A 股同一纪律；执行前后做只读侦察与结构验收。

## 5. 编排：新函数 `stock-value-hk`

```
1  读 dingtou_state 全量 → 提 data.stocks[].code → 筛 /^\d{5}$/ → 去重
2  空集 ⇒ 返回 {skipped:'no hk holdings'}；不发 GS 调用、不写表
3  三次 GS 调用（HK_stock 通道，HK_Q1 / HK_Q2 / HK_Q3）
4  适配器：剥 港股@ 前缀 → 代码补零到 5 位 → 按各列自己的日期戳取值
5  本地过滤到持仓码集合
6  纯函数算 roic_med / roic_min3 / roic_ok
7  upsert (batch_date, code)
```

第 1 步复用 `daily-update/index.ts:1563` 的 `heldStocksOf` 范式（持仓是按用户存的 JSON，不是关系表）。

第 4 步的取列规则：ROIC 按 `wantYears` 精确匹配三根年报列（守卫见 §5.1）；股息取 Y 年当期列 + 唯一的区间平均列；**PE 与 PB 各只返回一列，直接取值并把各自的戳落 `extras.stamps`，不做跨戳比较、不做时点对齐**（H-8：同批不同戳是平台常态，无法对齐）。

### 5.1 守卫（每条都有实测理由）

| 守卫 | 判据 | 理由 |
|---|---|---|
| 年报列数 | 恰好 3 根 | H-2：措辞正确时必为 3；变 7 说明措辞被改写成裸问法 |
| 年报戳形 | 三根全以 `1231` 结尾 | 防中报累计冒充当期（A 股决议 27 的原型事故） |
| 年报年份 | 等于 `wantYears` | 防跨年时取到旧窗 |
| 查询行数 | 任一查询返回 0 行 ⇒ 抛错 | 不写空批 |
| 持仓命中 | 命中数为 0 ⇒ 抛错 | 持仓非空却零命中，意味着代码形态或宇宙变了（H-6/H-7），必须炸而不是静默写空 |
| 单码缺席 | 某码在某次查询缺席 ⇒ 该次字段落 null + `extras` 记缺失，**不整批失败** | H-7：2792 vs 2577 是常态 |

**不设 `MIN_ROWS=4000` 那类全池下限**——那是 A 股全池批的守卫，港股落库行数是个位数，套用会恒假。上表「持仓命中」是它的等价替代。

凭据脱敏沿用 `gsValueFetch` 的做法：折叠 `TypeError`（其 message 含带 apiKey 的完整 URL）。日志不得出现 key 原值。

### 5.2 与 A 股函数的隔离

新函数独立目录 `supabase/functions/stock-value-hk/`。**不 import、不修改** `gs_value.ts` / `value_engine.ts` / `stock-value/index.ts`。三年中位与最差年的算法语义与 `roicStats` 一致，但**复制而非抽公共模块**——沿用 A3 复制体的既有纪律（V1.1 已冻结，两侧任一改动手工同步，由守卫测试钉住）。

## 6. cron

新 job `stock-value-hk-nightly`，`50 13 * * *`（21:50 北京）。

- 排在 A 股价值腿 21:45 之后 5 分钟。**无数据依赖**（不读 `stock_value`、不读主分），错开只为避免 GS 并发限流。
- `timeout_milliseconds := 300000`（pg_net 默认 5000ms 会把响应掐断，导致 `cron.job_run_details` 恒 succeeded 而实际成败不可见——A 股 2026-10-16 已踩过）。
- token 用 `$DAILY_UPDATE_TOKEN` 占位，真值不写入文件；执行后不得 `select job.command`。
- 文件：`scripts/cron_stock_value_hk.sql`。注册需用户明示。

## 7. 前端呈现

**位置**：股票详情页「价值评估」区，与 A 股同一位置、同一标题。用户不需要知道背后是两张表。

**路由**：`stockDetailFactsHtml`（`index.html:3873`）按 code 形态分流——5 位码走新 `valueAssessmentHkHtml`，其余分支一字不动。`valueGateHtml` 与 `swapSuggest` 在港股行天然返回空（都以 `stock_value` 行为输入），无需额外屏蔽。

**取数**：新 `loadStockValueHk()`，独立读，范式照 `loadIncomeWatch`（`index.html:912`）——先取最新 `batch_date`，再按持仓码取行。挂进 `index.html:854` 的 `Promise.all`。

**输出形态**（三行事实 + 两句常驻口径行）：

```
价值评估
资本回报    达标 · 近三年中位 15.86%（最差年 10.53%）
股息        0.88%（近五年平均 0.84%）
估值        PE 13.49 · PB 2.68
港股只报资本回报、股息与估值三项；不评估安全边际，也不与同业比较
资本回报以 8% 为参照线，按平台日历年度口径，可能与公司自身财年不完全对齐
```

文案纪律：

- **8% 露一次，在口径行**。A 股口径行不露阈值数字，因为它有「同行业中位」可看；港股没有任何同业参照，用户需要知道尺子是什么。达标/未达标仍只出现在资本回报行，不露算式。
- 缺失一律「无数据」，不显示 0、不显示 `NA` 缩写。
- 负号统一 U+2212「−」；`toFixed` 产出的 ASCII `-` 必须替换。
- 无 tier / vq / confidence / 四维雷达 / 门禁明细 / 换仓参考。
- `hasBatch=false` ⇒ 整区不出；`hasBatch=true` 但该股无行 ⇒ 「本批次无该股数据（未判定）」，沿用 `index.html:1190` 句式。
- **A 股现有文案逐字不变**，包括两句 `.value-note`。

## 8. 邮件端

**不动。** `daily-update/index.ts` 全文 0 处 `stock_value`——邮件本来就不取价值腿，港股同理不取。若日后要取，另开裁定。
