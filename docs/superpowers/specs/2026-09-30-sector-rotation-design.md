# 行业ETF板块轮动（Sector Rotation）设计规格

**版本**: V1.0（板块系统首版）
**日期**: 2026-09-30
**状态**: 待用户审阅
**关联**: 2026-09-26 股票评分 V1 设计、2026-09-27 V1.1 设计（renorm/失败纪律/fire-and-forget 均沿用）

## 0. 一句话目标

在基金页提供「行业ETF板块轮动榜单」：以行业代表ETF日K的均线体系分列向上/调整趋势，叠加经历史回测验证的少量信号标签，为用户选行业ETF（及其定投加减仓方向）提供参考；与个股系统分立，不合成、不互改分数。

## 1. 决策记录（本 spec 的裁决依据）

| # | 结论 | 依据 |
|---|---|---|
| S1 | **双系统分立**：个股板块系统（同花顺行业池，stock_score）与 ETF板块系统（本功能）并行；不建行业映射表，前端仅做"近似池提示"并标注口径不同 | R4 延伸裁决（国标↔同花顺映射维护成本不可控的先例） |
| S2 | **行业代理 = 行业代表ETF日K**，数据源为腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get`（qfq 前复权，640根/次按日期翻页，历史深度回 2019-01） | ETF 本身是行业成分 basket 且直接对应可买标的；东财 push2/push2his 已被 WAF IP 封禁（2026-09-28 批量触发，emweb/主站不受影响），禁止作为 K线源 |
| S3 | **标签规则以 2019-01~2026-09、121 行业代表ETF、冷却20日、全行业等权基准的回测证据为准**（见 §5 表）；三条翻案：多头状态不作买入推荐、"流入确认"反转为禁追标签、"退潮"不作卖出依据 | 用户已认可证据报告（2026-09-30） |
| S4 | **Q 景气因子**保留接口重试：gs-etf-filter 的 `hayjqidu` 当前无数据，每晚快照顺带探测；一旦回填，行业分权重从 V/M/L renorm(46/38/15) 回切 Q/V/M/L = 35/30/25/10 | 行业ETF四因子评分标准（既有约定）；renorm 架构天然支持双态 |
| S5 | 推荐输出口径：只出**状态、标签、相对位置和滚动历史统计脚注**，不出"买入X%"指令；风控性标签仅作展示标记，不影响行业分打分 | 与"风控措施仅作异常标记不扣分"纪律一致 |

## 2. 行业宇宙（universe）构建

1. **ETF 池**：gs-etf-filter 按 15 分段矩阵（规模段 2-10 / 10-30 / 30+ 亿 × 估值档 1-5）拉取行业型 ETF（class1=1），并集去重；每分段独立输出目录防同名覆盖；若某分段返回满 100 只则记 `truncated` 警告（覆盖闭合检查）。当前实测约 420 只。
2. **行业归一**：ETF 名称前缀提取行业名 → 按 `sector_etf_map` 归一到**规范行业名**。归一规则首版由人工种子 SQL 固化（约 140 提取名 → 约 110 规范行业），必做的合并示例：地产+房地产→房地产；券商+证券+证券保险→证券；芯片+集成电路+半导体+科创半导体→半导体（半导体设备单列）；酒+食品饮料 分列不合并。后续新增行业以"未归一个股名单"报警、人工补表。
3. **代表ETF**：每规范行业取规模最大的 1 只作为K线代理；榜单条目同时保留该行业全部 ETF 列表（前端可展开）。规模 <2 亿的 ETF 不入池（既有四因子约定）。
4. **刷新频率**：GS 15 分段截面**每晚都跑**（15 次调用，供当日 V/L/M 与 Q 探测）；宇宙成员构成与归一校验每周一重建。K线每晚只做增量。

## 3. 数据层

### 3.1 表结构

```sql
create table sector_etf_map (
  etf_code text primary key,
  etf_name text not null,
  canonical_ind text not null,        -- 规范行业名
  amt numeric,                        -- 最新规模(亿)
  is_rep boolean default false,       -- 是否该行业代表
  updated_on date
);

create table sector_kline (
  etf_code text,
  trade_date date,
  close numeric not null,
  volume numeric,
  primary key (etf_code, trade_date)
);

create table sector_rotation_daily (
  batch_date date,
  ind text,                           -- 规范行业名
  pk_etf text,                        -- 代表ETF代码
  n_etf int,                          -- 行业入池ETF数
  close numeric, ma20 numeric, ma60 numeric, ma120 numeric,
  m20 numeric, m60 numeric, pos52 numeric, dev60 numeric,
  vr numeric,                         -- 20/120 量比
  mp numeric, dm20 numeric,           -- 横截面动量分位 / 20日变化
  state text,                         -- 强多头|多头|纠缠|走弱|空头排列
  labels text[],                      -- 触发的标签集
  score numeric,                      -- 行业四因子分(renorm)
  v numeric, m numeric, l numeric, q numeric,  -- 分项(q 无数据时 null)
  theme text,                         -- 用户主题映射(可空)
  primary key (batch_date, ind)
);
```

### 3.2 数据获取纪律

- 腾讯K线：夜增量按 `lmt=5&end=今日` 拉取后只插缺失日期；代表ETF约 110 只 × 1 请求，**0.3 秒/请求 pacing + 3 次退避重试**；禁止无 pacing 突发（push2his 封禁教训）。
- GS 快照：**每晚 15 分段调用**；凭据沿用 memory.md / `COZE_GUOSEN_API_KEY_*` 模式，服务端环境变量注入，不落码。
- 失败处理：任何一路失败**保留昨日行并置 stale 标记列**（`stale boolean`），不整链中断；GS 分段触顶写 `warnings jsonb`。MIN_ROWS 守卫：并集去重后 <300 只视为快照异常，跳过宇宙重建。

## 4. 评分与榜单

1. **ETF 四因子分**（沿用既有标准）：Q35/V30/M25/L10；Q 无数据时 V/M/L 归一 46/38/15。V=估值档映射(5→100/4→80/3→60/2→40/1→20)；M=0.6×r60截面百分位+0.4×夏普截面百分位；L=规模截面百分位。
2. **行业分** = 该行业入池 ETF 分数的**规模加权均值**；同时存分项供前端 tooltip。
3. **趋势榜单**（用户点名口径）：按均线五态分列——「向上趋势榜」(强多头/多头，按 m60 降序)、「调整趋势榜」(走弱/空头排列，按 m60 升序)、「纠缠」计数；每行展示乖离MA60、20/60日涨跌、52周分位、ΔM20、量比、行业分、标签。
4. **主题映射列** `theme`：电力/绿电→电力、绿电；机器人→机器人；新能源车→新能源车、电池、充电桩；资源→资源、有色金属、稀土、煤炭、石油；美国/日本主题置空（A股无对应行业ETF，卡片注明不覆盖）。

## 5. 标签规则（最终集，含历史证据脚注）

| 标签 | 判据 | 角色 | 回测证据(60日前瞻, vs 全行业等权) |
|---|---|---|---|
| 筑底候选 | pos52≤20 且 m20>+2% 且 vr≤0.9 | **买入关注**（唯一） | 超额 +2.25pp，胜率 47.4%，n=173（置信中低，滚动复核） |
| 过热警示 | pos52≥90 且 dev60≥+15% | 回避 | 超额 -2.29pp，中位 -5.00，n=563 |
| 高位放量滞涨 | pos52≥70 且 vr≥1.8 且 \|m20\|≤2% | 回避（最强） | 超额 -2.34pp，n=196 |
| 禁追高 | dm20≥+20 且 vr≥1.2 且 m20>+2% | 警示（原"流入确认"反转） | 超额 -2.44pp，胜率 34.3%，n=639 |
| 退潮观察 | pos52≥70 且 dm20≤-20 | 中性观察，不扣分 | 超额 +1.46pp（不可作卖出依据） |
| 左侧埋伏 | pos52≤15 且 m20≤0 | 信息展示 | 超额 +0.78pp（证据弱，仅状态） |

- 均线五态定义：强多头=ma20>ma60>ma120 且 close>ma20；多头=ma20>ma60 且 close>ma60；空头排列=ma20<ma60<ma120 且 close<ma20；走弱=ma20<ma60 且 close<ma60；其余=纠缠。**多头状态不构成买入标签**（翻案①）。
- **历史不足处理**：代表ETF上市不足 250 根的行业参与榜单（显示状态与行业分），但 pos52/dm20 相关标签留空，行内标注"数据积累中(n=X)"。
- 每条标签前端脚注显示真实样本数与超额，数字随 nightly 滚动回测（最近 5 年窗口，每月重算一次写入 `label_stats` jsonb）。

## 6. Nightly 函数 `sector-trend`

- 形态：Deno Edge Function，`supabase/functions/sector-trend/`，纯函数内核 `engine.ts`（指标/状态/标签/renorm，含单测）+ `index.ts` 编排，沿用 stock-score 的部署（Management API）与触发链（pg_net fire-and-forget，5s 超时预期内）。
- 时点：**22:30**，接在 stock-score（21:30/22:00）之后，避开并发与配额。
- 步骤：①读宇宙映射 ②腾讯K线增量 ③GS 15 分段截面（每晚，含 Q 探测；周一额外宇宙重建+归一校验）④指标与截面分位计算 ⑤标签+评分写 `sector_rotation_daily` ⑥滚动月更 label_stats。
- 鉴权：独立 `SECTOR_TREND_TOKEN` 环境变量（沿用 DAILY_UPDATE_TOKEN 模式）。

## 7. 前端（基金页签「板块轮动」卡片）

1. 顶部概要：今日向上趋势 N 个 / 调整 M 个 / 纠缠 K 个 + 批次日期与 stale 提示。
2. 双榜单（§4.3 列全量），行内标签用色点+文字，点击行展开该行业 ETF 列表（代码/名称/规模/四因子分）。
3. 持仓主题条：六大主题各自映射行业的当前状态/标签；美国、日本主题显示"A股行业ETF不覆盖"。
4. 近似下钻提示：若同花顺侧存在名称近似的个股池，附一行"个股侧近似池：XX（分类口径不同，仅供参考）"；无近似则不显示。**不做跨系统分数合成**。
5. 数据读取：直查 supabase `sector_rotation_daily` 最新 batch_date，复用现有前端 supabase 客户端与自动刷新机制。

## 8. 测试与验证

- `engine_test.ts`：以真实K线段（512800、机器人ETF 各一段）做 fixtures；用例覆盖：五态判定各 1、六标签触发各 1 + 不触发边界各 1、renorm 权重回切（Q 有/无两态）、规模加权行业分。
- 部署后端到端：手动触发一次全链 → SQL 核对三个行业（银行/半导体/机器人）当日行与人工计算一致 → 前端渲染验证（含 stale 与主题映射）。
- 回测滚动复核：label_stats 月度重算结果偏离首版证据 >1pp 时，本 spec §5 需重审（写入 CHANGELOG）。

## 9. 非目标与边界

- 不覆盖美股/日本主题；不预测点位；不输出仓位指令。
- 不替代现有基金均线信号引擎——本卡片回答"哪个方向"，均线信号回答"何时买"，两者前端并列不合成。
- 东财 push2 家族在宇宙与K线链路中零依赖（仅未来若解禁可作校验源）。

## 10. 风险提示

本功能输出均为规则化状态标记与历史统计，不构成投资建议。
