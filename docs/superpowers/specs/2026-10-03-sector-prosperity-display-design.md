# 行业景气度展示（Prosperity Display）设计稿

**状态**：待用户评审 → 通过后转 writing-plans 出实现计划
**关联规则权威**：`docs/superpowers/specs/2026-09-30-sector-rotation-design.md`（本稿对其 S1 作局部澄清修订，见 §9）
**日期**：2026-10-03

## 1. 背景与目标

板块轮动四因子（Q35/V30/M25/L10）中，Q 景气腿依赖国信 `hayjqidu`，实测长期整表为空（0/94），四因子实际以 V/M/L 三腿 renorm 运行。前期调查（2026-10-03）结论：

- V/M/L 国信数据完整；仅 Q 缺。
- **不可复用 `stock_score` 的 growth/quality 分**：它们是「行业内百分位」，按行业聚合恒≈50，无跨行业区分度（实测证据）。
- 可用的是**绝对基本面**（营收同比增速、扣非净利同比增速、加权 ROE），可由国信智能选股宽表一次取全市场并按行业聚合（`stock-score/gs.ts` 的 `buildQFin()` 已验证该链路）。

**目标**：为板块轮动引入「行业景气度」这一**基本面维度信息**，辅助研判行业趋势。

**非目标（YAGNI）**：
- 不让景气度参与 `score` 排序（见 §2 裁决）。
- 不回填/改造原 `q` 腿（GS `hayjqidu` 探测链路保持原样，若未来 GS 真回填，按 S4 全局启用，与本特性正交）。
- 不做历史回补（景气度随每晚 GS 快照刷新，无历史序列）。
- 不改 `engine.ts`（评分内核冻结）。

## 2. 核心裁决：景气度只展示、不进入排序分

用户已选定 **方案①**。理由（本轮定论）：

局部覆盖（约 2/3 行业能可靠映射、1/3 主题为跨行业无单一归属）一旦把景气度塞进 `score`，会破坏横向公平：

1. **构成不可比**：有 Q 的行业是「4 维优秀度」、无 Q 的是「3 维优秀度」，同名分数不同义。
2. **选择性偏差（致命）**：缺 Q 的恰是科创芯片/数字经济等**主题板块**（高动量、资金驱动），在 M 权重被 renorm 抬高后系统性偏摆，且方向与「能否映射」相关——与吸引力无关的技术属性污染排序。
3. **时序抖动**：某行业补进映射表后，其分数从 3 腿跳 4 腿，基本面未变而分数跳档，榜单无端重排。

故：**行业分永远建立在统一口径的 V/M/L 三腿上**（全行业同基、可比）；景气度作为**并列展示信号**，不参与任何合成。

## 3. 与原 `q` 腿的关系（严格隔离）

| 概念 | 载体 | 是否进 score | 数据源 | 现状 |
|------|------|------------|--------|------|
| Q 腿 | `sector_rotation_daily.q` + engine `computeEtfFactors` | 进（全局 all-or-nothing） | GS `hayjqidu` | 恒 null，保留待 GS 回填 |
| 景气度 | **新列 `prosperity`（本稿）** | **绝不进** | GS 智能选股宽表绝对基本面聚合 | 本稿新增 |

二者物理隔离：`prosperity` 不进 `computeEtfFactors`、不改 `qAlive`、不碰 `engine.ts`。`q` 列继续按原逻辑（hay 空则 null、全局三腿）。这样即便未来 GS 回填 hay，score 走的是「全局统一」的 4 腿（S4），仍无本稿 §2 的局部不平衡问题。

## 4. 数据链路（nightly 新增步骤 ③.5）

在现有 `sector-trend/index.ts` 编排的 ③ GS 截面 之后、④ prevMp 之前，插入独立子流程：

```
③.5 景气度：
  a. 发一次 GS 智能选股宽表查询（全A股：营业总收入同比增长率、扣非净利润同比增长率、所属同花顺行业）
     —— sector-trend 自建精简适配器 gs_fund.ts（不跨函数 import stock-score）
  b. 解析每只股票的 {rev_yoy, kc_yoy, thsL1, thsL2}
  c. 按 同花顺 L2 分组，组内取中位数（对离群稳健）→ 行业原始景气 raw = 0.5·med(rev) + 0.5·med(kc)
  d. 跨行业对 raw 求百分位 → prosperity ∈ [0,100]（中位行业=50，刻度与 V/M/L 一致、可并排展示）
  e. 同花顺L2 → canonical 归因映射（§6）→ Map<canonical_ind, {prosperity, src}>
  f. 失败/无数据 → 返回空 Map，主链路照常（所有行 prosperity=null）
```

**隔离纪律**：③.5 任何异常只记 warnings，绝不 throw 中断 ③→④→⑤ 主链（仿 GS 截面失败的 stale 降级精神）。整轮景气度失败 ⇒ prosperity 全 null，板块分与榜单完全不受影响。

**配额**：每夜 +1 次 GS 调用（宽表一次返回全市场，与 `stock-score` 同量级；复用现有 `GS_API_KEY`）。

## 5. 景气度定义与刻度（决策定稿）

- **指标**：营业总收入同比增长率（rev_yoy）+ 扣非净利润同比增长率（kc_yoy），等权 0.5/0.5。
  - 理由：二者是最直接的「增长动能/景气」代理，正交于价格型 M 因子；ROE 偏「质量/盈利」不纳入景气主指标（可后续再议，本稿不做）。
- **行业内聚合**：中位数（抗个股离群/新股/异常值）。
- **跨行业刻度**：对各行业 raw 求百分位秩 → `prosperity` 0–100（与 V/M/L 同为 0–100，前端可同标尺并排）。
- **档位标签**：`高 ≥66` / `中 33–66` / `低 <33`（按百分位，展示用）。
- **样本下限**：某同花顺 L2 成分股 < 5 只 ⇒ raw 不可信 ⇒ 该行业 prosperity 不生成（映射端得 null）。

## 6. 同花顺 L2 → canonical 归因映射

canonical（ETF 名派生，约 102 个）与同花顺 L2（约 90 个）是**不同税onomy**，需归因。因景气度**仅展示**，映射采取「宁缺毋滥」的保守策略（错配只导致一个展示标签不准，不腐蚀任何分数）：

优先级：
1. **curated 主表** `CANON_TO_THS`：对重要且名称不一致的宽基行业人工钉映射（如 券商→证券、白酒→酿酒行业、半导体→半导体、芯片→半导体… 具体条目由实现阶段以真实数据枚举，见 §11 验收）。
2. **精确同名**：canonical 恰等于某 同花顺 L2 名。
3. **唯一子串**：canonical 与某 同花顺 L2 互为子串且**唯一命中**（多义/歧义 → 不猜，判 null）。
4. 其余（主题/跨行业类，如 科创芯片、数字经济、央企改革）→ **prosperity = null**，前端显示 `—`。

**未命中报警**：nightly 汇总「未映射到景气度的 canonical 行业」清单进 warnings（对齐 C1「只报警不新建」精神），供人工按需增补 curated 表（增量、可观测、不阻塞）。

**映射表落点**：`sector-trend/gs_fund.ts` 内纯数据常量 + 纯函数 `mapCanonicalToThs()`，可单测。

## 7. 存储 schema 变更

`sector_rotation_daily` 增两列（增量 `add column if not exists`，幂等，沿用 `migrate_sector_rotation.sql` 风格）：

```sql
alter table public.sector_rotation_daily add column if not exists prosperity numeric;   -- 0..100 或 null
alter table public.sector_rotation_daily add column if not exists prosperity_src text;   -- 归因来源：同花顺L2名 或 null（透明/可调试）
```

- `DailyRow` 接口 + `toDbRow` 增 `prosperity` / `prosperity_src`（null 合法）。
- **`score/v/m/l/q` 一字不改**——景气度纯附加。
- stale 复制行（C5）随昨日行带 prosperity（原样 copy，不重算），与既有 stale 语义一致。

## 8. 前端展示契约

- 板块行业卡在既有信息外，新增**独立「景气」展示**：数值 0–100（或 `—`）+ 高/中/低 档标签，来源标注 `同花顺L2`（悬浮或行内小字）。
- **不参与排序、不并入行业分、不做买卖建议**（纯状态展示，同「近似池提示」定位）。
- 渲染改动集中在 `scripts/sector_render_logic.ts`（前端门面纯函数，可单测）+ `index.html` 对应消费位。
- 缺值（null）显示 `—`，绝不显示 0（0 会被误读为「极低景气」，null 才是「无数据」）。

## 9. 对 spec S1「双系统分立」的局部修订

原 S1：个股系统（同花顺池）与 ETF 板块系统分立，「不建行业映射表、不做跨系统分数合成」。

**本稿澄清（非推翻，是精确化）**：
- 景气度数据源是 **sector-trend 自己发的国信查询**（与它读 V/M/L 同为「读国信」），**不读 `stock_score` 的输出表**——两系统仍各读各的，无跨系统数据依赖，「分立」实质未破。
- 景气度**不并入 `score`**——「不做跨系统分数合成」红线完全守住。
- 唯一新增的是「同花顺 L2 ↔ canonical」这一**同系统内的税onomy 归因映射**（§6），且保守缺省、仅服务展示。S1 当初警告的「映射表维护成本不可控」在展示场景下被大幅降级：错配无害、未命中留空、可观测增量补。

**S1 修订文本（追加一句）**：「板块系统可读取国信基本面并按同花顺行业归因展示景气度，前提是该景气度不参与 sector 评分合成、不引入对个股评分系统输出的依赖。」

## 10. 验证策略（TDD）

- **纯函数单测**（`gs_fund.ts` + 编排层）：
  - 宽表解析：列名前缀匹配、同花顺行业路径拆成 L1/L2、增速数值稳健解析（空/百分号/负值）。
  - 聚合：中位数、raw 合成、跨行业百分位刻度、样本<5 不生成。
  - 映射 `mapCanonicalToThs`：curated 命中、精确同名、唯一子串、多义判 null、主题判 null、未命中清单。
  - 隔离：③.5 抛错时主链不中断、prosperity 全 null、score 不变。
- **线上连通**：`mode=ping` 增探 GS 宽表一次（或独立 `?probe=fund`）。
- **前端**：`sector_render_logic` 景气度渲染纯函数测（null→`—`、档位边界、不显示为 0）。
- **回归**：`engine.ts` 不动 → 既有 `engine_test.ts`/`index_test.ts` 必须全绿（score/q 语义零变化是硬验收）。

## 11. 验收标准

1. 行业分 `score`、`v/m/l/q` 与本特性上线前**逐值一致**（景气度绝不进分）。
2. 每个可映射宽基行业显示景气度数值 + 档位 + 来源同花顺L2；主题/无归属行业显示 `—`。
3. GS 基本面调用失败时，板块榜单与分数完全不受影响，仅景气列全空并出 warnings。
4. 未映射行业清单在 nightly warnings 可见。
5. 全量测试绿；`engine.ts` 零 diff。

## 12. 风险与回退

- **风险**：GS 宽表基本面字段漂移（同比增速列名带日期戳）→ 以 `stock-score/gs.ts` 既有「前缀匹配、绝不硬编码日期」纪律规避。
- **风险**：主题行业永远无景气度 → 属预期内（§2/§6），展示 `—` 即为正确行为，非缺陷。
- **回退**：本特性为附加列 + 附加 GS 步骤 + 前端附加展示，回退 = 停 ③.5 步骤（`prosperity` 恒 null），主链与前端 `—` 自然降级，无需改 score 逻辑。
